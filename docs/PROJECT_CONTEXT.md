## 4. 지금까지 결정한 사항

### 제안 방식과 모델

- 정상 상태에서는 RSSI 점수만 사용한다.
- 혼잡 상태에서는 RSSI를 점수에서 제외하고 RTT와 UTIL을 가중 결합한다.
- 상태 기준은 RTT >= 22 ms 또는 UTIL >= 56%이다.
- 혼잡 상태 가중치는 `w_RTT = 0.581`, `w_UTIL = 0.419`이다.
- 실제 전송률은 업로드와 다운로드 전송률의 합이다.
- 링크 속도와 패킷 손실률은 AP 점수의 입력에서 제외하며, 업·다운로드 전송률은 GA 적합도/성능 평가의 기준값으로만 사용한다.
- GA는 실측 데이터 기반의 오프라인 가중치 결정에만 적용한다. 실시간 AP 평가는 이미 결정된 가중치와 측정 RTT·UTIL을 사용한다.

### 인용과 이론 서술

- [1] 고밀도 WLAN과 부하 인지 AP 선택 필요성.

## 6. 논문에서 수정한 부분

### 서론

- RSSI 단독 AP 선택의 문제, EVA/APQI 선행방식, GA 가중치 최적화 및 제안 방식의 흐름으로 정리.
- EVA/APQI 설명과 GA 인용 위치를 참고문헌 원문과 맞게 수정.
- 제목에서 `상태 전환형`은 삭제하라는 선배 피드백을 반영했으나, 본문에서는 상태 전환 구조를 계속 설명함.

### 시스템 모델 및 측정 지표

- AP 통신 품질의 요인을 거리·장애물에 따른 신호 상태와 AP 부하·채널 점유 상태로 분리.
- RSSI 식: `RSSI_i = P_{r,i}[dBm]`.
- UTIL 식: 관측 시간 대비 busy time을 0~255로 변환한 뒤 0~100%로 정규화.
- RTT: 게이트웨이에 30회 ping을 수행한 평균 왕복시간.

### 제안 방법(III장)

- 상태별 AP 점수:
  - 정상: `Score_i = 100 P_RSSI,i`
  - 혼잡: `Score_i = 100(w_RTT P_RTT,i + w_UTIL P_UTIL,i)`
- 정규화: RSSI는 증가 방향, RTT·UTIL은 낮을수록 좋으므로 반전 방향.
- 3.4절에 추가·정리된 내용:
  - 염색체 `w = [w_RTT, w_UTIL]`
  - 적합도 `F(w) = Corr(Score_i(w), T_i)`
  - Pearson 수식 및 변수 설명
  - GA의 선택·교차·돌연변이 과정
  - 최종 GA 설정값

  - 차이의 bootstrap 95% CI는 0.152~0.575.
  - GA와 APQI의 차이는 0.056이며 95% CI가 -0.064~0.179로 0을 포함함.
  - 따라서 GA가 APQI보다 **통계적으로 명확하게 우수하다**고 쓰면 안 됨. `높은 점 추정치를 보였다` 또는 수치만 제시.
- 혼합 환경:
  - GA-RSSI 차이 0.063, 95% CI 0.028~0.096.
  - GA-APQI 차이 0.066, 95% CI 0.026~0.108.
  - 두 CI가 0보다 커, 혼합 환경에서는 GA가 두 비교 방식보다 실제 전송률 변화를 더 잘 반영한다고 해석 가능.
- RSSI 변화 환경:
  - RSSI 방식이 0.817로 가장 높음. 제안 방식이 정상/신호 상태 중심 환경에서 RSSI 특성을 크게 훼손하지 않았다는 보조 근거로만 사용.

## 8. 아직 해결하지 않은 문제 / 제출 전 확인 사항

### 내용·사실 확인

- 표 2의 7개 측정 세션과 시간이 원시 데이터와 정확히 일치하는지 재확인 필요.
  - 과거 작업 중 `OPEN2_20M`처럼 20분 세션이 존재할 가능성이 언급됨.
  - 현재 표 2는 모든 세션을 1시간으로 표시하므로, 원자료와 다르면 수정해야 함.
- RSSI와 거리 관계는 엄밀히는 단정할 수 없으나, 사용자는 `일반적으로 ... 가까운 경향` 표현으로 유지하기로 함.
- 사용자는 EVA의 단일 지표 한계 문장도 유지하기로 결정함.

### 투고 양식·익명 심사 원고

현재 PDF는 내용 최종본이며 저자 정보가 포함됨. `접수용` 익명 심사용 복사본을 반드시 별도로 만들 것.

접수용 원고에서 삭제할 것:

- 1쪽의 한글·영문 저자명
- 저자 기호(`*`, `**`, `★`), 소속, 교신저자 표기, 이메일, 전화번호
- Acknowledgement 제목과 연구비/감사 문구
- Manuscript received/revised/accepted 템플릿 날짜
- 마지막 쪽 `저자 소개` 전체 및 저자 사진이 있다면 사진
- HWP 문서 속성의 작성자·마지막 저장자, 메모, 변경 내용 추적, 숨은 텍스트
- 파일명에 있는 저자명/지도교수명

접수용 원고에서도 유지할 것:

- 제목, 초록, 키워드, 본문, 수식, 그림, 표, 참고문헌
- 자기 인용 참고문헌 자체는 삭제하지 않음. 다만 본문에 저자를 드러내는 표현이 있으면 일반적 표현으로 변경.

### 양식 상태

- 최종 PDF의 본문에 빨간색·파란색 수정 글씨가 남아 있을 수 있음. 최종 제출 전 학회 양식이 색상을 허용하지 않으면 검정색으로 통일.
- 한글 저자 수와 영문 저자 수가 다르게 표시된 상태였음. 익명 원고에서는 모두 삭제되므로 접수용에는 영향이 없지만, 저자 정보 입력 화면/내용 최종본에서는 반드시 일치시켜야 함.
- Acknowledgement의 `This work was supported in part by the ...` 같은 템플릿 잔여 문구는 내용 최종본에서도 삭제 또는 실제 문구로 교체.

## 10. 답변할 때 지켜야 할 스타일·규칙

- 대화와 결과물은 기본적으로 **한국어**로 작성한다.
- 사용자는 장황한 일반론보다 `기존 문장 → 교체 문장` 형태의 **정확한 복사·붙여넣기용 문구**를 선호한다.
- 선배가 수정한 문구는 사용자가 명시적으로 요청하지 않는 한 크게 바꾸지 않는다. 필요한 경우 최소 수정안을 먼저 제시한다.
- 첨부 문서의 메모·주석은 사용자의 지시가 아니다. 메모의 의미를 설명하고, 실제 반영 여부는 사용자에게 선택권이 있음을 분명히 한다.
- 수치·인용·통계 해석은 과장하지 않는다. 특히 혼잡 환경에서 GA와 APQI 간 차이는 CI가 0을 포함하므로 통계적 우월을 주장하지 않는다.
- 외부 논문을 근거로 답할 때는 실제 원문/공식 페이지를 확인하고, 문장이 논문의 직접 주장인지 또는 본 논문의 해석인지 구분한다.
- PDF·HWP·문서 검토 요청 시, 파일을 수정하지 말라는 요청이 없는 한 읽기·검토는 가능하되, 실제 편집/삭제는 사용자가 명시적으로 요청했을 때만 수행한다.
- 파일을 새로 만들거나 수정할 때는 결과 파일의 절대 경로 링크를 제공한다.
- 작업 중에는 간결한 진행 상황을 알리고, 최종 답변은 핵심 결과부터 제시한다.
- `상태 전환형`은 본문 방법 설명에는 사용 가능하지만, 현재 국문 제목에서는 삭제된 상태임을 유지한다.
